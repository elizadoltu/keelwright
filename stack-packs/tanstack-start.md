# Stack pack: TanStack Start 1

## Summary

TanStack Start is a full-stack React framework built on TanStack Router. It provides full-document SSR, streaming, server functions (type-safe RPC), middleware, and server routes, and builds with Vite or Rsbuild [S1]. Start is stable. This pack covers `@tanstack/react-start` 1.169.x, which brings breaking changes for apps upgrading from the release candidate (see Version notes) [S2][S27]. React Server Components are experimental [S1].

## Project structure

- Required packages are `@tanstack/react-start`, `@tanstack/react-router`, `react` and `react-dom`. Dev dependencies are `vite` and `@vitejs/plugin-react`, plus `typescript`, `@types/react`, `@types/react-dom` and `@types/node` [S7]. `package.json` sets `"type": "module"` [S7].
- `vite.config.ts` imports `tanstackStart` from `@tanstack/react-start/plugin/vite`. `tanstackStart()` must come **before** `viteReact()` in `plugins` [S7]. The official `start-basic` example also adds `tailwindcss()` and, for deployment, `nitro()` from `nitro/vite`, and sets `resolve.tsconfigPaths: true` [S20].
- `src/routes/__root.tsx` is the root route and holds the document shell. `<HeadContent />` goes in `<head>`, and `<Scripts />` goes at the end of `<body>` [S21].
- `src/router.tsx` exports `getRouter()`, which calls `createRouter({ routeTree, scrollRestoration: true, ... })` [S7][S21].
- `src/routeTree.gen.ts` is generated by the router plugin during dev and build [S21]. Commit it: it is "part of your application's runtime, not a build artifact" [S24]. Exclude it from linters and formatters, and mark it read-only in VS Code with `files.readonlyInclude`, `files.watcherExclude` and `search.exclude` set to `"**/routeTree.gen.ts": true` [S25].
- Type safety comes from registering the router once through module augmentation of `@tanstack/react-router`'s `Register` interface, rather than importing the router instance into each file [S23].
- `src/start.ts` is optional. It calls `createStart(() => ({ requestMiddleware, functionMiddleware, defaultSsr }))` for global configuration [S8][S14].
- Server code: create server functions with `createServerFn` from `@tanstack/react-start`. Organize files as follows [S3]:
  - `*.functions.ts` holds `createServerFn` wrappers and is safe to import anywhere.
  - `*.server.ts` holds server-only helpers such as database queries, imported only inside handlers.
  - Files with no suffix hold client-safe types, schemas and constants.
- Server routes (HTTP endpoints) live in `src/routes` next to page routes and declare `server.handlers` [S15].

## Naming

File-based routing conventions in `src/routes` [S10]:
- `__root.tsx` is the root route.
- `index` matches the parent path exactly.
- `$param` is a dynamic segment, and a lone trailing `$` is a splat [S15].
- A `.` separator creates flat nested routes, e.g. `posts.$postId.tsx`.
- A `_` prefix creates a pathless layout route, e.g. `_authed`. A `_` suffix un-nests a route from its parents.
- A `-` prefix excludes files and folders from the route tree, which is useful for colocated components and utilities.
- `(group)` folders do not appear in the URL.
- `route.tsx` is a directory's own route.
- `[x]` escapes special characters, e.g. `script[.]js.tsx`.

Most projects mix flat and directory routes [S10]. File suffixes carry meaning: `.server.*` and `.client.*` opt a file into import protection [S5][S18], and `.functions.ts` marks server-function modules [S3]. Name tests `*.test.tsx` next to the code they cover [S13].

## Testing

- **Unit and component tests:** Vitest with Testing Library (`@testing-library/react`, `jest-dom`, `user-event`) and jsdom [S13]. Keep tests next to the source, e.g. `Header.test.tsx` beside `Header.tsx` or `posts.test.tsx` beside the route file. Put shared helpers such as `setup.ts`, `router-utils.tsx` and `mock-routes.tsx` in `src/test/` [S13].
- **Routes:** Render routes through `RouterProvider` with a router built from `createRootRoute`/`createRoute`/`createRouter` and a `createMemoryHistory({ initialEntries })` [S13].
- **End-to-end tests:** Playwright, with `playwright.config.ts` and specs in `e2e/`, run against the dev server [S13]. E2E covers what unit tests can't: SSR and hydration, server functions, and middleware.
- **Testable logic:** Keep business logic in plain functions in `*.server.ts` or no-suffix modules. Test them directly, without going through `createServerFn`.

## Linting and formatting

- Use `@tanstack/eslint-plugin-router` with `...pluginRouter.configs['flat/recommended']`. The plugin key is `@tanstack/router` [S6].
- `@tanstack/router/create-route-property-order` is recommended and auto-fixable. It enforces the property order that type inference depends on: `params`/`validateSearch` → `loaderDeps`/`ssr` → `context` → `beforeLoad` → `loader` → `head` and the rest [S28].
- Exclude `routeTree.gen.ts` from Prettier, ESLint and Biome [S25]. The official example ships a `.prettierignore` [S19].
- TypeScript settings recommended by the docs are `jsx: react-jsx`, `moduleResolution: Bundler`, `module: ESNext`, `target: ES2022`, `skipLibCheck` and `strictNullChecks`. Keep `verbatimModuleSyntax` **disabled**, because it "can result in server bundles leaking into client bundles" [S7].

## Security

- **Code is isomorphic by default.** Route loaders run on the server during SSR and on the client during navigation, so secrets used in a loader leak [S5][S17]. Put secret-bearing logic in `createServerFn` (callable over RPC) or `createServerOnlyFn` (throws on the client) [S5].
- **Import protection** is on by default. It uses `mock` in dev and `error` in build. It blocks `**/*.server.*` and `@tanstack/react-start/server` from client bundles, and `**/*.client.*` from server bundles. You can also mark a file with `import '@tanstack/react-start/server-only'` [S18]. Configure it with `tanstackStart({ importProtection: {...} })`, and don't disable it [S18].
- **Environment variables:** Only `VITE_` variables (or `PUBLIC_` on Rsbuild) reach the client, and they are bundled into the JavaScript, so never use those prefixes for secrets [S4]. Read `process.env` inside handlers or middleware `.server()`, not at module scope, which can leak values or be `undefined` on edge runtimes [S4][S5]. Validate env with Zod, gitignore `.env.local`, and declare types in `src/env.d.ts` [S4].
- **Authorization:** `beforeLoad` and `_authed` layout routes are UX guards, "not the security boundary for the data". Every server function and server route that touches private data must authorize the request itself [S3][S9].
- **CSRF:** Without `src/start.ts`, Start installs CSRF middleware for server functions automatically. Once you define `src/start.ts`, add `createCsrfMiddleware()` yourself [S3][S8]. Requests without `Sec-Fetch-Site`, `Origin` or `Referer` are rejected [S3].
- **Server functions are same-origin endpoints.** Use server routes for public or cross-origin APIs [S3][S15].
- **Validation:** Validate input with `.validator(...)` (Zod or another Standard Schema library) [S3]. Client-sent middleware context (`sendContext`) is not validated at runtime, so validate it and derive the session from server state [S8].
- **Sessions:** `useSession` was removed. Use a library such as iron-session, or a hosted provider: Clerk, WorkOS, Better Auth or Auth.js [S2][S9]. Set cookies with `httpOnly`, `sameSite: 'lax'` and `secure` in production, and use a `SESSION_SECRET` of at least 32 characters. Hash passwords with bcrypt, scrypt or argon2. Rate-limit with shared storage such as Redis [S9].
- **Caching:** Never send `Cache-Control: public` for identity-dependent responses. Use `private` with `Vary`, or `no-store` [S3][S9].
- **Cookies:** Add cookies with `setCookie` or `appendResponseHeader`. `setResponseHeader('set-cookie', …)` replaces all cookies [S2].

## Performance pitfalls

- **Code splitting:** Use automatic code splitting (`autoCodeSplitting`) where supported, or `.lazy.tsx` files with `createLazyFileRoute`. Keep loaders in the critical bundle, and note that `__root.tsx` cannot be split [S11].
- **Dynamic imports:** Don't dynamic-import server functions, which causes bundler issues. Import them statically and the build replaces them with RPC stubs [S3].
- **Loader cache keys:** `loaderDeps` must list exactly the search params the loader uses. Returning the whole `search` object causes needless reloads [S26].
- **Loader timing:** `beforeLoad` runs serially and loaders run in parallel, so put fetching in `loader` to avoid waterfalls [S26].
- **Defaults:** `staleTime` defaults to 0, `gcTime` to 5 minutes and `defaultPreloadStaleTime` to 30 seconds. With TanStack Query, set `defaultPreloadStaleTime: 0` [S26].
- **Hydration mismatches:** Values that differ between server and client, such as `new Date().toLocaleString()`, cause mismatches. Set them in `useEffect`, or use `<ClientOnly>` or `useHydrated()` [S5][S17].
- **Selective SSR:** Use `ssr: false` or `'data-only'` per route for code that needs browser APIs. Children can only make SSR more restrictive [S14].
- **Prerendering:** Static pages can be prerendered with `tanstackStart({ prerender: { enabled: true, crawlLinks: true } })` [S22].

## CI/CD and release

- **Scripts:** The official example uses `dev: vite dev`, `build: vite build && tsc --noEmit`, `preview: vite preview` and `start: node .output/server/index.mjs` (Nitro) [S19]. Run lint, `tsc --noEmit`, Vitest and Playwright in CI.
- **Hosting:** Cloudflare Workers (`@cloudflare/vite-plugin`, `wrangler.jsonc` with `main: @tanstack/react-start/server-entry`), Netlify (`@netlify/vite-plugin-tanstack-start`, publish `dist/client`), Railway, Vercel, Node/Docker and Bun via Nitro (`nitro/vite`), and Appwrite [S12]. Bun requires React 19 or later [S12].
- **NODE_ENV:** `server.build.staticNodeEnv` defaults to `true`. If you disable it, set `NODE_ENV=production` at runtime [S4].
- **Requirements:** Router tooling requires Node `^20.19.0 || >=22.12.0` and Vite 6 or later [S27]. Start 1.169 targets Vite 8 [S2].
- **Bundle check:** Check the client bundle for server-only code before release [S5][S17].

## Conventions

- **Clean Architecture:** Keep the dependency rule by layer:
  - Domain and use-case code lives in plain TypeScript modules with no framework imports, e.g. `src/domain/`, or server-only use cases in `*.server.ts`.
  - Adapters are `createServerFn` wrappers in `*.functions.ts` and server-route handlers. They validate, authorize, call a use case and return serializable data [S3][S15].
  - Routes (loaders and components) are the outer UI layer and call server functions only.
  - Import protection mechanically keeps `*.server.*` code out of the client layer [S18].
- **Atomic Design:** Start does not dictate component structure. Put atoms, molecules and organisms under `src/components/`. Route files in `src/routes/` act as pages. Colocate route-only components in `-components/` folders, which the `-` prefix excludes from the route tree [S10].
- **Humble Object:** Keep route components, loaders and server-function handlers thin: parse with `validateSearch` or `.validator()`, delegate to pure functions, and render. Unit-test the pure functions with Vitest and cover the thin boundaries with Playwright [S13][S16].

## Version notes

- **RC → 1.x stable** [S2]:
  - Upgrade to Vite 8.
  - `.inputValidator()` was renamed `.validator()` on server functions and middleware.
  - `useSession` was removed in favour of session libraries. Existing session cookies cannot be read by the new library.
  - `@tanstack/nitro-v2-vite-plugin` was replaced by `nitro()` from `nitro/vite`.
  - `createStartHandler` rethrows errors, and custom entries use `createServerEntry` with `handleStartError`.
  - Uncaught errors return a generic JSON 4xx/5xx body.
  - Response helpers override returned responses.
  - `setResponseHeader('set-cookie')` replaces all cookies.
  - `getRequestHeader` returns `''` for a present but empty header.
  - `sendContext` is `undefined` when not sent.
- **Recent router tooling** [S27]:
  - Node 21 and 22.0–22.11 are no longer supported.
  - Vite 5 is no longer supported.
  - `plugin.hmr.style` and `codeSplittingOptions.compilerPlugins` were removed.
  - The esbuild plugin throws if `autoCodeSplitting` is enabled.
- **Search params:** With Zod v4, pass schemas directly to `validateSearch`. Zod v3 needs `zodValidator` and `fallback()` from `@tanstack/zod-adapter` [S16].
- **Serialization:** Server function `strict` serialization is on by default. Keep it [S3].
