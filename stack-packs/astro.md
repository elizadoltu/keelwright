# Stack pack: Astro 7

## Summary

Astro is a web framework for content-driven sites. Pages are rendered to static HTML by default, and interactivity is added only where needed as "islands" of UI framework components [S14][S20]. This pack covers Astro 7 (researched against 7.4.x). Astro 7.0 was released on 2026-06-22. It brings Vite 8 (Rolldown), a Rust `.astro` compiler, Sätteri as the default Markdown processor, advanced routing via `src/fetch.ts`, and stable route caching [S2][S1].

## Project structure

- `src/pages/` is the only reserved directory, and it is required. Every `.astro`, `.md` or `.mdx` file in it becomes a route [S3][S4]. Dynamic routes use bracketed names (`[slug].astro`, `[...path].astro`). Files and folders starting with `_` are not built, so helpers and tests can sit next to the pages that use them [S4].
- `src/components/`, `src/layouts/` and `src/styles/` are common conventions, not requirements [S3].
- `public/` holds assets that are served without processing, such as `favicon.svg`, `robots.txt` and `CNAME` [S3][S17]. Images that Astro should optimize belong in `src/` [S13].
- `astro.config.mjs` is recommended over `.js` and `.ts` in most cases. `tsconfig.json` is recommended [S3].
- `src/content.config.ts` defines build-time content collections, and `src/live.config.ts` defines live collections [S16].
- `src/actions/index.ts` exports the `server` object of actions [S15].
- `src/middleware.ts` (or `src/middleware/index.ts`) exports a named `onRequest` [S18].
- `src/env.d.ts` declares `App.Locals` [S18].
- `src/fetch.ts` is **reserved in v7** for advanced routing. If it exists, it replaces the request pipeline. The `fetchFile` option changes the path, and setting it to `null` disables advanced routing [S1][S4][S10].
- `.astro/types.d.ts` is generated by `astro sync`. Include it in `tsconfig.json` and do not edit it [S11][S12].

## Naming

- Route files are named after their URL segment. Parameters go in brackets (`[post].astro`), and rest parameters use `[...path]` [S4].
- The docs' example trees use PascalCase component files (`Header.astro`, `Button.jsx`) [S3].
- Collections are named by the keys of the exported `collections` object [S16]. Actions are named by their keys in `server`, and those names become public endpoint names [S15].
- Environment variables that client code may read are prefixed `PUBLIC_` [S6].

## Testing

- **Unit and integration tests** use Vitest. Build `vitest.config.ts` with `getViteConfig()` from `astro/config`, so tests load the Astro config. A second argument overrides settings such as `site` [S5].
- **Component tests** render `.astro` components with the Container API: call `experimental_AstroContainer.create()` from `astro/container`, then `container.renderToString(Component, { props, slots })`, and assert on the HTML [S5]. In v7, import `getContainerRenderer()` from each integration's `container-renderer` entrypoint (for example `@astrojs/react/container-renderer`), not from the package root [S1].
- **End-to-end tests** use Playwright (`npm init playwright@latest`). Run them against a production build: `webServer.command: 'npm run preview'` with `url: 'http://localhost:4321/'` [S5]. Cypress and Nightwatch are documented alternatives [S5].
- **Content Security Policy** is not applied in `astro dev`. Test it with `astro build` followed by `astro preview` [S10].

## Linting and formatting

- **Formatting:** Prettier with the official `prettier-plugin-astro` [S7]. Add it to `plugins` in `.prettierrc` and add an override that sets `"parser": "astro"` for `*.astro` files. Plugins such as `prettier-plugin-tailwindcss` must be listed last [S7].
- **Linting:** `eslint-plugin-astro`, which the Astro docs list as community-maintained [S7]. It is ESM-only and needs ESLint 10 or later [S9]. Use a flat `eslint.config.mjs` that spreads `eslintPluginAstro.configs.recommended`. Add `typescript-eslint` for TypeScript inside components [S9]. For accessibility, use the `jsx-a11y-recommended` config, which needs `eslint-plugin-jsx-a11y` [S9].
- **Rules worth adding** beyond `recommended`: `astro/no-set-html-directive` and `astro/no-unsafe-inline-scripts` (security), `astro/no-unused-css-selector`, and `astro/jsx-a11y/alt-text` [S8]. The rules `astro/no-omitted-end-tags` and `astro/valid-compile` are deprecated, so don't use them [S8].
- **Alternatives:** Biome has experimental `.astro` support covering only the frontmatter, and dprint can format `.astro` files with the `markup_fmt` plugin [S7].
- **Type checking:** neither `astro dev` nor `astro build` type-checks. `astro check` runs diagnostics, including inside `.astro` files, and exits with code 1 on errors [S11][S12].

## Security

- **XSS:** `set:html` is "not automatically escaped by Astro". Pass it only trusted or sanitized strings [S21]. Expressions in templates are escaped.
- **Secrets:** declare variables in `env.schema` with `envField.*` [S6]. Secrets use `context: "server", access: "secret"` and are imported from `astro:env/server`. Client values must be `context: "client", access: "public"`, because client secrets are not supported. Set `validateSecrets: true` to fail at startup instead of on first import. Only `PUBLIC_*` values from `import.meta.env` reach client code. `astro.config.mjs` cannot read `import.meta.env` and must use `process.env` or Vite's `loadEnv` [S6].
- **CSRF:** `security.checkOrigin` defaults to `true`. It returns 403 for cross-origin unsafe requests to on-demand pages, so keep it on [S10].
- **Forwarded host:** `security.allowedDomains` (default `[]`) is needed before Astro trusts `X-Forwarded-Host` [S10].
- **Content Security Policy:** enable `security.csp` to hash the scripts and styles Astro emits (default algorithm `SHA-256`). Add policy with `security.csp.directives` [S10]. `astro/no-unsafe-inline-scripts` flags inline scripts that defeat it [S8].
- **Actions are public endpoints.** Validate `input` with Zod (`z` from `astro/zod`) and check authorization in each `handler`, or gate actions in middleware with `getActionContext()`. Throw `ActionError` with a code such as `"UNAUTHORIZED"` [S15].
- **Remote images:** only sources allowed by `image.domains` or `image.remotePatterns` are processed. `image.dangerouslyProcessSVG` defaults to `false` and should be enabled only for trusted sources [S10][S13].

## Performance pitfalls

- **Shipping JavaScript by default.** Components render with no client JavaScript unless they have a `client:*` directive [S14]. Use `client:load` only for UI that must be interactive immediately. Prefer `client:idle`, `client:visible` (below the fold or heavy components) or `client:media` [S21]. `client:only` must name its framework, for example `client:only="react"` [S21][S8].
- **Personalized fragments blocking the cache.** Use server islands (`server:defer`) with fallback content so the page shell can be cached while dynamic parts render separately [S14]. Route caching (`cache`, `routeRules`, `memoryCache()`) is stable in v7 [S1][S2].
- **Unoptimized images.** Images in `public/` and plain `<img>` tags bypass optimization. Use `<Image />` and `<Picture />` from `astro:assets` with images in `src/`. These set `width` and `height` to avoid layout shift, and a responsive `layout` generates `srcset` and `sizes` [S13].
- **`define:vars` on scripts** implies `is:inline`, so the script is not bundled and runs once per render [S21].
- **Rendering everything on demand.** Start with the default `output: 'static'` and opt individual routes out with `export const prerender = false` [S20].
- **Prefetching.** `prefetch.defaultStrategy` defaults to `'hover'`. `prefetchAll` is on by default only with `<ClientRouter />` [S10].

## CI/CD and release

- Run `astro check` in CI. It exits 1 on errors and is intended for CI workflows; `--minimumFailingSeverity` controls the threshold [S11]. The docs suggest `"build": "astro check && astro build"` [S12].
- `astro build` writes to `dist/`, plus server output for on-demand routes. `--timings` shows build hotspots [S11]. `astro preview` is for local checks only and is "not designed to be run in production" [S11].
- On-demand routes need an adapter (`npx astro add node`, `netlify`, `vercel` or `cloudflare`) [S20].
- On GitHub Pages, deploy with `withastro/action@v6` and `actions/deploy-pages@v5`. Commit the lockfile so the package manager is detected, and set `site` (and `base` for project pages) [S17].
- Node.js "v22.23.4 or higher" is required, and odd-numbered versions are not supported [S19].
- Upgrade with `npx @astrojs/upgrade`, which updates `astro` and official `@astrojs/*` integrations together [S2].

## Conventions

- **Clean Architecture:** maps partially. Astro pages, endpoints, actions and middleware are the outer (framework) layer. Keep domain logic and use cases in plain TypeScript modules under `src/` (for example `src/lib/` or `src/domain/`) that do not import `astro:*` modules or `Astro`. Only route files, actions and middleware import them, so dependencies point inward. Astro prescribes no layering beyond `src/pages/` [S3]. The `astro:env` and `astro:content` virtual modules work only inside the Astro context [S6], which makes them adapter-layer dependencies.
- **Atomic Design:** applicable to `src/components/` [S3]. Atoms and molecules are `.astro` components with no client JavaScript. Organisms may be framework islands with a `client:*` directive. Templates map to `src/layouts/`, and pages to `src/pages/`. Keep hydration at the organism level so most of the tree ships no JavaScript [S14].
- **Humble Object:** keep `.astro` frontmatter, action `handler`s, `src/fetch.ts` and `onRequest` thin. They parse the request, call a plain function, and render or return the result. Test that function with Vitest [S5], and test the humble shell through the Container API or Playwright [S5].

## Version notes

Changes in Astro 7 [S1][S2]:

- **Vite 8 with Rolldown.** Integrations that depend on Vite internals may need updates.
- **Rust compiler is the only compiler.** Remove `experimental.rustCompiler`. Unclosed non-void tags are now build errors, and invalid nesting is no longer auto-corrected. CSS serialization changes slightly: named colors become hex, and quotes in `url()` may change.
- **`compressHTML` now defaults to `'jsx'`.** Whitespace between inline elements is stripped, so add `{" "}` where it matters.
- **Markdown uses Sätteri by default.** `remarkPlugins`, `rehypePlugins` and `remarkRehype` require installing `@astrojs/markdown-remark` and setting `markdown.processor: unified()`.
- **`src/fetch.ts` is reserved** for advanced routing, which is on by default.
- **Now stable:** `logger` (top-level, with `logHandlers.json()`), `cache` and `routeRules`. Move them out of `experimental`. `queuedRendering` is now the default, so remove the flag.
- **Removed:** `@astrojs/db`; use `node:sqlite`, Drizzle or another library. The `astro:transitions` constants (`TRANSITION_*`) and helpers (`isTransitionBeforePreparationEvent()`, `isTransitionBeforeSwapEvent()`, `createAnimationScope()`) are gone. Use the event name strings such as `'astro:after-swap'` instead.
- **Deprecated:** `getContainerRenderer()` from integration package roots. Import it from the `container-renderer` entrypoint.

Third-party blog posts give a different minimum Node version. Follow the official install page [S19].
