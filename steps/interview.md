# Step: `interview`

> **Not implemented yet.** This step is added in Phase 1 build step 3 (spec section 9). Tell the user, don't change the state, and stop.

## Purpose

Read the project description and specs, identify the project type (web, mobile, game, ai, library), and interview the user to close gaps: users, platforms, scale, constraints, non-goals, integrations, content sources, dynamic features, languages, SEO / performance priorities.

## Produces

- `.keelwright/interview.md` — questions asked and answers given
- Project type recorded with `STATE set project-type <type>`

## Gate

None. Continues straight to `prd`.
