# Run: esn-fm (2026-11-18)

The first real `/adopt` run (spec 8.1, Phase 2 build step 6): a social app for an ESN section, built without a Claude setup. A clone of the owner's repository, on the branch `keelwright-adopt`.

- KeelWright 0.1.0, project type `web`, toolchain `node`; adopted as **one project** with two npm workspaces (`frontend/`, `backend/`)
- Stack in use: React 19 + Vite 7 + Tailwind 4 + TanStack Query 5 + React Router 7 (Vercel); Express 5 + node-postgres 8 + zod 3 (Railway); TypeScript 5, Node 20
- Steps 1–3 and the gates were driven headless (`claude -p`) with the owner's answers; `gaps` and `generate` were run interactively by the owner. `publish` was skipped (not requested)
- Wall time: 10:24 to 14:03, most of it waiting at the gates; the steps themselves took about 25 min

## Result

- **No application code changed.** The changes outside `.keelwright/`, `docs/` and the Claude setup are the 8 approved tooling fixes: gitleaks in a hook and CI, Node pinned to 20 (`.nvmrc`, `engines`, every `setup-node`), Vitest runners in both workspaces, `typecheck` and `check` tasks, `check` on every PR, the HRA- PR title rule (`pr-validation.yml`), Dependabot, and `.claude/settings.local.json` ignored.
- `npm run check` passes across both workspaces; `generatecheck` passes; every document passes `doccheck`. A gitleaks scan of the full history (76 commits) found no leaks.
- Generated setup: `CLAUDE.md` (987 words), 7 scoped rule files, 3 subagents, 5 skills (one project-specific: `new-endpoint`, the routes/api/validators triplet that is the most repeated task), the hooks with a per-workspace formatter config, and a new `CONTRIBUTING.md`. 16 pack rules were set aside with a reason in `.keelwright/generate.md`, 8 of them because the owner chose the project's way at gate 2.
- Recorded, not fixed: Node 20 past end of life, TypeScript two majors behind, and **Railway stops reading `railway.json` on 2026-12-01** (G-10, found by the Railway pack research) — with the migration steps for the owner.

Found while reading the code and told to the owner (not changed — `/adopt` describes, it doesn't fix application code): the error handler returns `err.message` on 500 responses; it reads `err.errors` where zod documents `err.issues`; the pg pool has no `error` listener; React Router 7.10.1 has open-redirect advisories (no exploitable path found).

## Findings

| # | Finding | Fix |
|---|---|---|
| 1 | **Headless sessions refused combined commands** (`&&`, `>>`) and `git log`, so `STATE start analyse` was lost with the command it was chained to. | `commands/adopt.md` and `commands/kickoff.md`: `STATE start` runs on its own, before any work; `git log/show/status/ls-files/branch` added to the headless tool list (`scripts/lib/claude.mjs`) |
| 2 | **`doccheck` read code as file paths.** `req.body`, `err.message` and `res.status(500)` in backticks were reported as missing files; dotfiles like `.nvmrc` were never checked. | `citedPaths`: a path needs a `/`, a known file extension, a known extensionless name (Makefile, Dockerfile…) or a leading dot |
| 3 | **Continuing one session made a small step expensive.** The driver resumed the same session for each gate, so a two-minute approval carried the research step's context and cost $16.40; the headless part cost $31.67 in all, three times the estimate. The eval runner did the same. | `evals/lib/runner.mjs`: a gate is re-opened and approved in a fresh session — the pipeline resumes from its files and needs no earlier context |
| 4 | **A pack researched for a major the project can't use.** Vitest wasn't in the project, so `research` covered Vitest 5; `gaps` then installed 4.1.12 because Vitest 5 needs Node ≥ 22.12. `generate` noticed and kept only the rules that hold for 4.x. | Open: `research` should resolve a tool that `gaps` will add against the runtime pin, or `gaps` should flag a pack whose major differs from what it installs |
| 5 | **Bugs noticed during analysis have nowhere to go.** The four code findings above were only in the chat. | Phase 3: the doctor (spec 7.0) records findings with evidence; until then, `analyse` could list them in the analysis under Risks |

Noted, no change:

- The owner kept the HRA- PR title rule although none of the last 15 PRs followed it; the new check will fail this run's own PR unless its title has an HRA- key. `gaps` said so; it is the owner's decision.
- Node is now pinned to 20 where Railway's Nixpacks had defaulted to 18: the next backend deploy changes runtime. Worth a test deploy before merging.
- Cost of the interactive steps wasn't recorded (the owner's subscription).
